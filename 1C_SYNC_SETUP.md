# Паллета: автоматическая выгрузка из 1С в GitHub Pages

**Статус: сценарий передачи готов, но источник CSV в 1С и Windows-планировщик ещё не настроены.** Это не онлайн-интеграция с 1С и не автоматический заказ. Каждый цикл использует отдельную проверенную выгрузку.

## 1. Что публикуем, что не публикуем

Репозиторий `shmlr/palleta-menu` публичный. Файл `products.json` в нём тоже доступен каждому.

**Разрешено только**: код номенклатуры для поиска, публичное название SKU, фасовка, розничная цена для обычного покупателя на кассе, *доступное для интернет-заказа* количество, дата и время фиксации. Если раскрывать точное количество нежелательно, в выгрузку надо передавать безопасный лимит, например `max(0, фактически доступно – резерв – страховой запас)`, а не полный внутренний складской остаток. Доступное количество может быть округлено вниз. Если режим продажи особый (клубная карта/акция), рассчитывать его отдельно, не смешивая с обычной ценой.

**Запрещено**: закупка, себестоимость, GP, поставщики, персональные данные клиентов, движения, весь справочник 1С, полные отчёты и данные авторизации. Никаких паролей в репозитории и скриптах.

## 2. Где запускается автоматизация

На Windows-ПК магазина, у которого есть разрешённый доступ к 1С и стабильное соединение с GitHub. Не в GitHub Actions: облачный runner **не должен подключаться напрямую к внутренней 1С**.

Схема:

`1С УТ/Розница → согласованная CSV только публичных SKU → проверка в Windows → sync_1c_export.py → products.json → git push → GitHub Pages`.

Файлы для Windows: `sync_1c_export.py` и `run_1c_sync.ps1` уже в репозитории.

## 3. Контракт выгрузки CSV

Разделитель `;`, кодировка UTF-8 или UTF-8 с BOM. Обязательные заголовки:

```csv
sku_code;retail_price;stock_quantity;captured_at;unit;stock_unit
УТ-00003202;54,90;80;2026-10-09T18:00:00+03:00;кг;кг
```

Это только **пример формата**, не утверждение о цене/остатке. Для фасовки `pricing_mode=by_pack`: розничная цена **за одну потребительскую упаковку**, `stock_quantity` в целых упаковках и `stock_unit=pack`. Для весового SKU: цена за `unit`, остаток в той же единице. `captured_at` — время *фактической выгрузки* со смещением часового пояса, не фиктивная дата запуска скрипта.

`sku_code` должен соответствовать полю 1С `Номенклатура.Код для поиска` **поштучно**. Сейчас в каталоге сопоставлено **9 из 21** SKU; остальные требуют верификации кода и фасовки. До завершения сопоставления они остаются с неопределёнными ценами/остатками.

Экспортируем **все 9 уже сопоставленных кодов на каждом цикле**, включая товары с нулевым остатком. Если строка товара пропадёт из CSV, процесс останавливается: это лучше, чем оставить ложное «есть в наличии».

## 4. Один раз на Windows

1. Установить Git и Python 3.11+; проверить `git --version`, `py --version`.
2. Создать каталог `D:\PalletaMenu`, затем выполнить:
   `git clone https://github.com/shmlr/palleta-menu.git D:\PalletaMenu`
3. Создать `D:\PalletaExport`; доступ к CSV дать только локальному пользователю задания и сотруднику 1С, не всему магазину.
4. Настроить безопасную авторизацию GitHub на ПК (например, Git Credential Manager с fine-grained токеном только для `shmlr/palleta-menu`, permission `Contents: Read/Write`). **Не вписывать токен** в `.ps1`, CSV, `.json` или командную строку.
5. Один раз подготовить правильный файл `D:\PalletaExport\approved_public_prices_stock.csv` через штатный отчёт/обработку 1С, сверить 9 кодов, фасовки, одну цену на кассе и доступный остаток с директором.
6. На ПК выполнить тестовый запуск:

```powershell
cd D:\PalletaMenu
py sync_1c_export.py --csv D:\PalletaExport\approved_public_prices_stock.csv --dry-run --require-all-codes --max-age-minutes 20
```

Только после `PASS` запускать:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\PalletaMenu\run_1c_sync.ps1
```

Если нет желания менять политику выполнения в командной строке, подпишите скрипт и запустите его в разрешённом локальном режиме PowerShell. Запуск должен быть от отдельной Windows-учётной записи с минимальными разрешениями.

## 5. Автоматизировать выгрузку *на стороне 1С*

Настроить у специалиста по вашей конфигурации 1С (УТ 11 / Розница 2) внешнюю обработку или регламентное задание, которое **каждые 30 минут** создаёт новую CSV с ценой для обычной продажи и доступным остатком *только разрешённых SKU*, с фиксацией фактического времени. Запись производить во временный файл, затем атомарно заменять `approved_public_prices_stock.csv`, чтобы Windows не прочитал половину выгрузки.

**Не предлагать непроверенный код 1С как рабочий:** имена регистров, ценовых видов, организаций, магазинов, свободного остатка и резерва надо сверить в конкретной базе. Для принятия обработки нужны 2 контрольные строки (весовой и фасованный SKU) и фактическая сверка с кассой.

## 6. Планировщик Windows

В «Планировщике заданий» создать `Palleta Public Catalog Sync`. Отдельная учётная запись, выполнение каждые 30 минут (через 3–5 минут *после* задания выгрузки 1С). Действие: `powershell.exe`; аргументы:

`-NoProfile -ExecutionPolicy Bypass -File "D:\PalletaMenu\run_1c_sync.ps1"`

Начальная папка: `D:\PalletaMenu`. Запретить параллельный повтор второго экземпляра. Установить журналирование ошибок/вывод в контролируемый локальный журнал. Задание должно останавливаться при CSV старше 20 минут, неполном списке сопоставленных SKU, неверной единице измерения, нулевой цене или отсутствии доступа к GitHub. **Никакого тихого подстановочного остатка**.

## 7. Контроль после запуска

- 1С экспортировал 9 из 9 сопоставленных кодов (затем 21/21, когда завершено сопоставление).
- Источник `retail_price` проверен на применимую розничную цену по кассе.
- `stock_quantity` — доступно к продаже за вычетом резерва, единицы корректны.
- Выгрузка не старше 20 минут на момент синхронизации.
- `products.json` обновился в коммите GitHub, GitHub Pages успешно опубликовал коммит.
- В корзине пессимистично учитывается количество всех покупок на неделю; при нехватке товара разрешён аналог или другое блюдо.
- Тест OOS: установить одному тестовому SKU ноль в **тестовой CSV**, убедиться в замене, после чего восстановить реальный экспорт.

## Важно

Это публичная статическая витрина, **не подтверждение резерва**. Между публикацией данных и сборкой заказа товар может быть продан. Указанные цены/остатки истекают через 24 часа и 60 минут соответственно; окончательное наличие и чек подтверждает магазин.
