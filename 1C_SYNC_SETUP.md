**Решение владельца, 09.10.2026:** цены передаются **из УТ 11 в Розницу**. Поэтому для сервиса «Меню на неделю» используем **только УТ 11** для выгрузки подтверждённых розничных цен и доступных к заказу остатков. Отдельный поток из Розницы не нужен.

**Фактический статус:** алгоритм, скрипт проверки CSV и публикация через GitHub подготовлены. Экспорт из рабочей базы УТ и Планировщик заданий Windows **не настроены и не запускались**. Сервис ещё не получает реальные остатки автоматически.

Владелец сообщил: **«Оптовая, RUB» — цена для держателей карт Паллеты**. В меню выбираем этот вид цены, а обычную «Розничная, RUB» в расчёт клубной корзины не подставляем. «Закупочная, RUB» запрещена к публичной выгрузке.

## Подтверждено 12.10.2026: один склад Паллеты

Владелец подтвердил: **в УТ 11 один склад «Паллета Петра 1», торговый зал магазина «Паллета»**. Объединять остатки разных складов не требуется. Внешняя обработка в УТ должна выбирать фактический склад **по проверенной ссылке справочника**, а в CSV писать этот ключ.

Требуется проверить именно **доступный к продаже остаток**, не только учётное количество: брак, страховой запас и возможное участие расширения Simple WMS (резервов по данным владельца сейчас нет). Без подтверждения доступности выгрузку публичных остатков не запускать.

Окружение: платформа **8.3.25.1394**, УТ **11.5.20.97**, серверная база и тонкий клиент. Установлены, среди прочих, расширения **Simple WMS** и **«Интернет-магазин + 1С»**. Их фактическое влияние на складские данные или обмен ещё не проверено. Подготовка выгрузки должна быть READ-ONLY, без изменения конфигурации и расширений.

## Контроль отчёта 13.10.2026 и правило без резервирования

**Подтверждено владельцем:** на текущий момент **резервирования товаров нет**. Не требуем от пользователя дополнительного отчёта по резервам и не создаём фиктивный модуль резервирования. Если резервирование появится позже, это будет изменением контракта данных.

В отчёте «Ведомость по товарам в ценах номенклатуры» (13.10.2026) по единственному складу **«Паллета Петра 1»** показаны:

- Картофель: единица **кг**, код в колонке с обрезанным названием «Номенклатура.К…» — `УТ-00003202`, совпадает с кодом каталога.
- Рис «Мистраль Янтарь» 900 г: единица **шт**, артикул `10213`, код в колонке «Номенклатура.К…» — **`УТ-00001079`**. Точное название реквизита за обрезанным заголовком не подтверждено; перед использованием в `sku_code` проверить, что это именно `Номенклатура.Код для поиска`. До проверки `sku_code=null`, `ut_report_code=УТ-00001079`.
- Колонка **«Оценка»** отражает учётную стоимость, **не подтверждённую цену «Оптовая, RUB»**. Не использовать «Оценка / Количество» как клубную цену.
- В фильтре отчёта выбран параметр **«Только товары с оценкой»**. Этот отчёт не доказательство полноты ассортиментного списка. Для регулярной выгрузки отбор нужно формировать по утверждённому whitelist, включая товары с нулевым остатком.

**Правило доступного количества при отсутствии резервов [Предлагаемое]:** `max(0, остаток торгового зала - подтверждённые исключения брака/недоступного товара - согласованный страховой запас)`; если Simple WMS содержит дополнительные ограничения, учитывать их после проверки. Ни величину исключений, ни страховой запас не выдумывать. При отсутствии надёжных данных об исключениях/доступности — STOP, не отправлять в сайт сырой остаток под названием `available_quantity`.

**Блокирующие проверки для автоматизации:** точный реквизит кода, реальная клубная цена «Оптовая, RUB», исходный показатель свободного к продаже товара и отсутствие неучтённых блокировок Simple WMS. После подтверждения можно настроить единственную READ-ONLY выгрузку.

## 1. Что нужно подтвердить в УТ 11 перед началом

1. **Вид цены.** Выбран «Оптовая, RUB» для держателей клубной карты; сверить реальную цену на кассе с картой. В УТ могут быть и закупочные, и клубные, и другие виды цен: они не должны подменять клубную цену. Сверить 2–3 SKU с чеком/кассой до запуска. Дополнительные скидки поверх клубной цены пока не рассчитываем.
2. **Магазин и склад.** Подтверждён один склад, торговый зал Паллеты. CSV использует `store_key=PALLETA_TRADE_HALL`, обработка УТ использует проверенную реальную ссылку склада.
3. **Доступный остаток.** Резервов пока нет (подтверждено владельцем); учитывать брак, непригодный к продаже остаток, согласованный страховой запас. Если в УТ нет правдивой доступности товара на полке, нельзя выдавать его за «в наличии»; нужно сначала наладить обмен/сверку.
4. **Коды.** `sku_code` из поля `Номенклатура.Код для поиска`, соответствие фасовки. Сейчас 2/21 кодов в whitelist. Для риса 10213 — подтверждённый артикул, но не поисковый код. Не сопоставлять автоматически только по похожему названию.

**Изменение контракта 13.10.2026:** после сверки файлов УТ и min-max установлены коллизии короткого кода поиска (поиск-код встречается у разных внутренних кодов). Поэтому нужен `internal_code` = точный `Номенклатура.Код` вместе с `sku_code` = `Номенклатура.Код для поиска`, а **не** автоматическое отсечение префикса `УТ-` или похожее название. Валидатор отклоняет неполные/несогласованные пары. Подробнее в [инструкции ручной сверки](./tools/README_STAGE.md). Сам CSV-пример ниже целиком тестовый; не публиковать его как актуальный остаток или клубную цену.

## 3. Формат **единственной** CSV из УТ

UTF-8 или UTF-8 BOM; разделитель `;`. Заголовки строго в указанном порядке:

```csv
store_key;internal_code;sku_code;price_type;club_price;price_unit;available_quantity;stock_unit;captured_at
PALLETA_TRADE_HALL;УТ-00003202;3202;Оптовая, RUB;54,90;кг;20;кг;2026-10-09T18:00:00+03:00
```

**Все значения во второй строке — демонстрационные, не факты Паллеты.** Ключ `store_key` и вид клубной цены в примере уже определены как контракт интеграции. Цена, остаток и время **демонстрационные** и должны быть заменены на реальные значения из УТ. Время должно отражать фактический момент среза с часовым поясом. Использовать атомарную запись (временный файл → переименование), не выдавать старый файл за новый.

- `sku_code`: строго `Номенклатура.Код для поиска`; `internal_code`: строго `Номенклатура.Код`. Оба должны совпадать с явным whitelist в публичном `products.json`. Короткий код не является уникальным.
- `price_type`: **ровно один** утверждённый вид клубной цены, один и тот же для всех строк; скрипт требует соответствия параметру `-PriceType`.
- `club_price`: действующая цена, рубли (две цифры после запятой максимум). Фасованные позиции: цена одной потребительской упаковки, `price_unit=pack`. Весовые: цена за `кг`/другую соответствующую единицу.
- `available_quantity`: ограниченный объём, реально доступный к продаже, а **не полный сырой остаток**, с учётом резервов, брака и страхового запаса. Фасованные позиции: целые упаковки и `stock_unit=pack`.
- `captured_at`: фактический момент выгрузки; не старше 20 минут во время импорта. Каждая выгрузка содержит **оба сопоставленных SKU**, в том числе позиции с нулевым остатком. Неизвестные позиции не публикуются.

В GitHub не допускаются закупочные цены, наценка, GP, поставщики, личные данные, полные внутренние остатки, пароли и исходные CSV. Допускается публикация только одобренных данных о конкретных SKU.

Компиляция и выполнение в реальной УТ 11.5.20.97 ещё не подтверждены. По выданному списку имён регистров и полей подготовить отдельную проверенную обработку экспорта 2 SKU, а затем полный whitelist.

## 4. Запуск Windows после настройки экспорта УТ

1. Установить Python 3.11+ и Git на ПК с доступом к УТ 11. Создать `D:\PalletaExport`; установить права доступа. Настроить ограниченную запись в **один** репозиторий `shmlr/palleta-menu` через Git Credential Manager или иной согласованный безопасный механизм. Не хранить токен в скрипте.
2. Клонировать: `git clone https://github.com/shmlr/palleta-menu.git D:\PalletaMenu`.
3. Настроить регламентную обработку УТ, экспортирующую **один** CSV `D:\PalletaExport\ut_public_catalog.csv` каждые 30 минут. Реальные регистры УТ, вид цены, точку и доступный остаток определить после проверки базы.
4. Первый прогон (без записи):

```powershell
cd D:\PalletaMenu
py sync_ut_catalog.py --csv D:\PalletaExport\ut_public_catalog.csv --store-key "PALLETA_TRADE_HALL" --price-type "Оптовая, RUB" --dry-run
```

5. Только после `PASS` и сверки 2–3 товаров, ручной запуск:

```powershell
powershell.exe -NoProfile -File D:\PalletaMenu\run_1c_sync.ps1 -StoreKey "PALLETA_TRADE_HALL" -PriceType "Оптовая, RUB"
```

6. В Планировщике заданий Windows выполнять команду из пункта 5 **каждые 30 минут** через несколько минут после регламентной выгрузки УТ. Не допускать параллельных запусков, настроить журнал ошибок и контроль отсутствия новых публикаций.

## 5. Пороговые проверки

- Единый технический `store_key=PALLETA_TRADE_HALL`, выбранный вид `price_type=Оптовая, RUB` и проверенная ссылка склада торгового зала в УТ.
- Все сопоставленные 2/2 кодов присутствуют, одинаковый вид цены и магазин на каждой строке, нет дубликатов и лишних SKU.
- Цена больше нуля, максимум две десятичные цифры; фасованный остаток — целое количество; единицы соответствуют каталогу.
- Время реальной выгрузки моложе 20 минут, есть смещение часового пояса.
- Ошибки любого вида = STOP без нового коммита. На сайте старые остатки через срок свежести станут «уточняются».
- Тест нулевого остатка: ноль в тестовом CSV приводит к предложению замены SKU или другого блюда. **Тестовые остатки никогда не загружать на публичный GitHub.**
