# УТ 11.5.20.97: внешний диагностический .epf для Паллеты

**Стадия:** исходник модуля формы подготовлен в [`EPF_Metadata_Probe_Form.bsl`](./EPF_Metadata_Probe_Form.bsl). Это **не готовый .epf**: .epf требуется один раз создать и проверить в установленном Конфигураторе 1С. Сборка и запуск на живой базе пока НЕ проверены.

## Назначение и правила

- Один склад **«Паллета Петра 1»**. Для CSV используем только внешний условный идентификатор **`PALLETA_TRADE_HALL`**, он не является GUID/ссылкой 1С.
- Вид клубной цены: **«Оптовая, RUB»**.
- Проверенные **`Номенклатура.Код для поиска`**: **`3202`** (картофель) и **`1079`** (рис Мистраль Янтарь, 900 г); артикул риса — `10213`, это другой реквизит.
- Владелец сообщил, что **резервов нет**. Это не отменяет необходимости проверки заблокированного/бракованного товара и возможного влияния Simple WMS.
- Скрипт читает **только структуру метаданных**, не выполняет запросы к записям номенклатуры и регистров, не пишет в 1С, CSV или GitHub. Он намеренно **не является** автоматическим экспортёром.

## Как создать диагностическую обработку в Конфигураторе

1. Открыть свою УТ **в Конфигураторе**, предпочтительно в тестовой копии базы.
2. **Файл → Новый → Внешняя обработка**; дать имя `ПаллетаДиагностикаУТ`.
3. Добавить **управляемую форму** и сделать её основной формой обработки.
4. Создать **реквизит формы** `РезультатДиагностики` типа **Строка, неограниченная длина**. Перетащить его на форму, включить многострочное отображение и при возможности режим «Только просмотр».
5. Создать **команду формы** `ПроверитьМетаданные` и поместить кнопку с этой командой на форму. В свойстве **Действие** команды указать процедуру `ПроверитьМетаданные`.
6. Открыть **модуль формы** (не модуль объекта) и вставить целиком исходник [`EPF_Metadata_Probe_Form.bsl`](./EPF_Metadata_Probe_Form.bsl).
7. Выполнить **проверку синтаксиса средствами Конфигуратора**. При ошибке сохранить диагностическое сообщение и остановиться, не «подбирать» имена регистров.
8. Сохранить файл как `ПаллетаДиагностикаУТ.epf` на локальном ПК. **Обновлять конфигурацию базы данных не требуется**.
9. Открыть в режиме **1С:Предприятие → Файл → Открыть** этот .epf, нажать `ПроверитьМетаданные`. При предупреждении о внешней обработке убедиться, что открывается именно ваш локально созданный файл.
10. Скопировать в чат **только секции** по `Номенклатура`, `Склады` / `СкладыИМагазины`, `ВидыЦен`, `ЦеныНоменклатуры` / `ЦеныНоменклатуры25`, `ТоварыНаСкладах`, `ТоварыКОтгрузке`, а также кандидаты, связанные с Simple WMS. Если какой-либо объект отсутствует, сообщить это; **не** угадывать.

Если список слишком большой, отфильтруйте текст по указанным словам. Не передавайте логины/пароли, строку подключения к серверу, данные клиентов или полный дамп базы.

## Что делаем после отчёта

1. Выберем точный регистр цен для **вашего** режима ценообразования 11.5.20.97, его измерения (вид цены, характеристики, упаковка, дата) и ресурс цены. В зависимости от режима 11.5 может использоваться `ЦеныНоменклатуры` или `ЦеныНоменклатуры25`: это **не подтверждено для конкретной базы**.
2. Проверим реальную ссылку одного склада и регистр/показатель, который соответствует **доступному к продаже**, а не просто учётному количеству, с учётом Simple WMS.
3. Составим внешнюю **READ-ONLY** обработку экспорта **двух SKU**; проверим совпадение с ценником и отчётом.
4. Затем расширим whitelist, настроим экспорт `D:\PalletaExport\ut_public_catalog.csv` и только после `--dry-run PASS` включим отправку в GitHub.
5. В GitHub отправляется лишь разрешённый `products.json`, а не полный учётный остаток/себестоимость.

## Ограничение

**Сборка .epf и прямое чтение регистров вашей базы не выполнены:** для этого требуется установленный Конфигуратор и доступ к серверной базе. Сам исходник — диагностический прототип до проверки синтаксиса и разрешений в вашем окружении.
