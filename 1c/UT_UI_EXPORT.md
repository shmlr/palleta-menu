# Паллета: ручная выгрузка через обычный интерфейс УТ 11.5.20.97

**Решение пользователя 13.10.2026:** на текущем этапе работать **только в обычном интерфейсе УТ («Такси»)**. Не открывать Конфигуратор, не запускать внешние обработки .epf, не изменять регистры и расширения. Стандартная интеграция по CSV и GitHub пока НЕ активирована. Цель — сперва сверить реальные штатные экспорты Excel без изменений базы.

## Что подтверждено

- Одна серверная база 1С УТ 11.5.20.97; один склад **«Паллета Петра 1»** (торговый зал), резервов пока нет со слов владельца.
- Для покупателей с клубной картой используется вид цены **«Оптовая, RUB»**.
- В отчёте **«Ведомость по товарам в ценах номенклатуры»** видна колонка **«Номенклатура.Код для поиска»**. По состоянию на 13.10.2026: картофель `3202` (кг), рис Мистраль Янтарь 900 г `1079` (шт; артикул `10213`).
- В форме **«Печать ценников из документа»** при выборе «По виду цен» → «Оптовая» на 13.10.2026 показаны клубные цены: картофель **49,96 ₽/кг**, рис **179,97 ₽/шт**.
- Учётные конечные остатки в предоставленном снимке: картофель **823,316 кг**, рис **5 шт**. Это не онлайн-остатки и не подтверждение фактически доступного к продаже количества; на сайт как `available_quantity` НЕ загружались.
- «Оценка запасов: По учетному виду цен склада» из ведомости НЕ является клубной ценой и НЕ используется для корзины.

## Какие файлы экспортировать из стандартного интерфейса

**Файл A — номенклатура и остатки.** В уже открытом отчёте **«Ведомость по товарам в ценах номенклатуры»** оставить склад **«Паллета Петра 1»**, дату отчёта и выбрать нужные товары. Убедиться, что видна полная колонка `Номенклатура.Код для поиска`; экспортировать в **Excel (.xlsx)** через штатную команду сохранения табличного документа. Не использовать сумму «Оценка» как цену по клубной карте.

**Файл B — клубные цены.** Использовать уже открытый экран **«Печать ценников из документа»**, установить **«По виду цен» → «Оптовая»**, корректную дату, включить те же товары. Попытаться сохранить/выгрузить отображаемую таблицу через доступное в интерфейсе `Ещё`/штатный механизм, предпочтительно **.xlsx**. Если штатного экспорта таблицы в этой форме нет, не подменять источник: прислать скриншот меню `Ещё`, затем выбрать другой штатный отчёт цен, доступный в вашей УТ.

**Не надо вручную переписывать цены в CSV, не делать подстановку между товарами только по похожему названию.** При необходимости связывать выгрузки по `Код для поиска`; если этот код отсутствует в ценовой форме, только по отдельно подтверждённому точному соответствию (например, карточка товара с проверенным штрихкодом, фасовкой и кодом), а не по нечеткому названию.

## Обработка после получения двух файлов

1. Сначала прочитать структуру листов, колонки, единицы измерения, дату отчёта и признак клуба.
2. Проверить нулевые остатки, итоги/группы отчёта и отсутствие дубликатов; в номенклатуру не должны попадать строки «Итого», «РД», «Рынок 2» и папки.
3. Проверить точное соответствие `Код для поиска`, артикула, единицы хранения, упаковки и клуба. Для фасованного риса цена за **1 шт (потребительская упаковка 900 г)**.
4. Сформировать локальный **предварительный** Excel/CSV для проверки, прежде чем записывать `products.json`; на GitHub не отправлять суммы «Оценка», закупочные цены, поставщиков, данные покупателей и непроверенный складской остаток.
5. В ручном режиме публиковать цены как **срез с указанной датой**, не как текущую онлайн-цену, и остаток оставлять со статусом `unknown`, если доступность не подтверждена. Для автоматического режима нужна новая проверка перед каждым срезом; файл Excel, сохранённый вручную, не является автоматической синхронизацией.

## Статус

Сейчас доступны только скриншоты двух контрольных товаров. Исходные .xlsx из обычного интерфейса ещё не получены. Без них нельзя достоверно написать и проверить парсер конкретной формы отчётов. Исходник EPF в репозитории остаётся неиспользуемым вариантом на будущее; он не требуется для этого этапа.
