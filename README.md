## Решение по 1С (09–12.10.2026)

**Владелец подтвердил:** цены из УТ 11 передаются в Розницу. Для меню выбрана одна база-источник: **УТ 11, клубная цена + доступный к заказу остаток конкретной точки**. Розница остаётся для кассовой и выборочной контрольной сверки, но не является источником отдельного CSV и не требуется для планового обновления сайта.

Вид клубной цены **«Оптовая, RUB»** уже выбран; его применение на кассе с картой ещё нужно сверить на контрольном чеке. Остатки должны быть **доступными для продажи**, после резервов и исключений, а не общими складскими балансами.

**12.10.2026:** владелец подтвердил единственный склад, торговый зал Паллеты. Для CSV используем наш технический ключ `PALLETA_TRADE_HALL` (это не код/UUID 1С); реальная ссылка склада должна быть проверена в УТ. Резервы, брак и возможное участие Simple WMS в расчёте доступного остатка ещё требуют сверки.

### Формат единственного утверждённого CSV

Все названия столбцов обязательны, один магазин и один вид цены:

```csv
store_key;sku_code;price_type;club_price;price_unit;available_quantity;stock_unit;captured_at
PALLETA_TRADE_HALL;УТ-00003202;Оптовая, RUB;54,90;кг;20;кг;2026-10-09T18:00:00+03:00
```

Вторая строка полностью **тестовая**. Для SKU с продажей упаковками обе единицы = `pack`, а цена указывается за 1 упаковку. Нельзя выгружать сюда закупочные цены, внутреннюю экономику, клиентов, токены и исходные полные остатки.

Прогон без изменений каталога:

```powershell
py sync_ut_catalog.py --csv D:\PalletaExport\ut_public_catalog.csv --store-key "PALLETA_TRADE_HALL" --price-type "Оптовая, RUB" --dry-run
```

Только после сверки с магазином и настройки GitHub-авторизации:

```powershell
powershell.exe -NoProfile -File D:\PalletaMenu\run_1c_sync.ps1 -StoreKey "PALLETA_TRADE_HALL" -PriceType "Оптовая, RUB"
```

**12.10.2026: проверен складской отчёт УТ.** Единственный склад в отчёте — «Паллета Петра 1». Картофель учитывается в кг, фасованный рис 900 г в штуках. Это учётный остаток, а не доступность к заказу.
Для риса `10213` оказался артикулом, а новый снимок полного поля `Код для поиска` подтвердил `1079`; код картофеля — `3202`. Уточнённый whitelist: **2/21** кода; остальные прошлые коды ожидают проверку.
Исторические значения остатка из ведомости в публичный каталог **не вносились**. Подробности в [инструкции](./1C_SYNC_SETUP.md).

**13.10.2026:** владелец подтвердил **отсутствие резервов**. Новый отчёт УТ показывает код риса `УТ-00001079` (обрезанный заголовок поля «Номенклатура.К…»), картофеля `УТ-00003202`, а `10213` отдельно указан как артикул риса. Пока реквизит не сверён с `Код для поиска`, код риса сохраняется только как кандидат `ut_report_code`, без включения в автоматический whitelist. «Оценка» — не клубная цена, полный складской остаток не публикуем. 

**13.10.2026: подтверждены поисковые коды и клубные цены** из двух форм УТ: `3202` (картофель, 49,96 ₽/кг) и `1079` (рис Мистраль 900 г, 179,97 ₽/уп.). `10213` — артикул риса. Скриншоты содержат учётные остатки, но не гарантированную доступность; цены занесены только как `manual_club_snapshot`, не как живые.

Остальные 7 прежних `УТ-...` кодов сохранены в `legacy_sku_code` до проверки колонки «Номенклатура.Код для поиска». **Активный whitelist: 2/21.** Фактическая синхронизация УТ в GitHub ещё не настроена.

## Статус

- **Готово:** приложение на Pages, логика корзины, подбор аналогов, код валидатора единственного экспорта УТ, локальные тесты.
- **Не сделано:** реальная регламентная выгрузка из УТ 11, подтверждение вида цены, магазина и реального доступного остатка, настройка заданий Windows, сопоставление всех товарных кодов (сейчас 2/21).
- Пока нет подтверждённой свежей выгрузки, интерфейс не должен обещать актуальный остаток или точную итоговую стоимость. Даже после подключения данные на сайте не являются резервом: магазин подтверждает цену и наличие при приёме заказа.

Данные `products.json` публично доступны через GitHub Pages. Публиковать разрешено только одобренные значения и безопасную квоту доступного количества.
