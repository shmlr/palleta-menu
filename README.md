# Паллета — меню на неделю (пилот v0.3)

Публичный статический сайт для формирования **предварительного меню на 7 ужинов** и **заявки на уточнение корзины**. Это пилот, **не интернет-магазин** и не обещание актуальных цен/остатков. Без сервера, без подключения к 1С, без оплаты.

## Файлы

- `index.html` — мобильный интерфейс;
- `app.js` — подбор блюд, состав корзины, выбор доступных аналогов;
- `products.json` — товары, фасовки, цены, история сверок, альтернативы по ингредиентам;
- `recipes.json` — 11 рецептов из предыдущего MVP, количества ингредиентов на одного человека;
- `.github/workflows/pages.yml` — попытка публикации через GitHub Actions (может потребоваться включить GitHub Pages в Settings).

## Как обновлять цену

В `products.json` для конкретного товара (`products` по `id`) обновите:

```json
"price": 109.90,
"price_as_of": "2026-10-09T17:20:00+03:00",
"price_source": "current_retail"
```

`price` для `pricing_mode: "by_pack"` — цена **одной упаковки**. Для `pricing_mode: "by_weight"` — цена за 1 `unit` (например, кг). Не ставьте `current_retail`, если значение получено из исторической выручки или закупочной цены.

Цены с давностью более 24 часов (см. `price_freshness_hours`) считаются историческими. Для массового обновления подготовьте разрешённую **публичную** выгрузку 1С с `sku_code, retail_price, unit, package_size, updated_at`. Исключите закупочную цену, GP, поставщиков, скидки конкретных клиентов и любые персональные данные. Автоматическая выгрузка **пока не настроена**.

## Как обновлять наличие

Подтверждённый товар:

```json
"availability": "in_stock",
"availability_checked_at": "2026-10-09T17:20:00+03:00",
"stock_quantity": 7
```

Нет товара:

```json
"availability": "out_of_stock",
"availability_checked_at": "2026-10-09T17:20:00+03:00",
"stock_quantity": 0
```

Неизвестно: `availability="unknown"`, `availability_checked_at=null`, `stock_quantity=null`. Наличие старше 60 минут (`stock_freshness_minutes`) **не считается подтверждённым**. Это защитное правило для пилота, не гарантированный интервал обновления 1С.

## Алгоритм замены

Рецепт ссылается на ингредиент (`ingredient`), а не на SKU. Для ингредиента указаны `product_ids` по приоритету; при подтверждённом наличии выбирается доступный SKU, при неизвестном остатке предлагается предварительный вариант с предупреждением. При подтверждённом отсутствии всех совместимых вариантов рецепт исключается. Покупатель может вручную переключаться между совместимыми вариантами, но наличие всё равно требует подтверждения. `substitution_hint` — **гипотеза для проверки ассортиментом**, не товар и не доказательство наличия.

Количество закупки округляется до целых фасовок/шагов веса, затем стоимость считается отдельно. Сумма неполной или устаревшей корзины **не объявляется итогом заказа**. Продукты с несовместимыми единицами не заменяются автоматически (например, молоко 950 г нельзя без проверки перевести в литры).

## GitHub Pages

В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**. После разрешения Actions workflow `.github/workflows/pages.yml` развернёт сайт. Если Pages или GitHub Actions отключены настройками репозитория, публикация не будет работать до их включения владельцем.

Проверки до отправки покупателям: открытие на телефоне, прохождение анкеты, цены и округления, соответствие номенклатуры, фактический остаток, проверенный WhatsApp, согласование текста и условий доставки. Кнопка WhatsApp намеренно не подключена до подтверждения номера.

Не размещайте в публичном репозитории внутренние выгрузки 1С и коммерческие данные магазина.
