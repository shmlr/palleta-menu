# Паллета — семейное меню на неделю

## v1.5: 3 или 7 дней и «Уже есть дома» (14.10.2026)

По умолчанию подбор на **3 дня** (9 приёмов пищи), можно выбрать 7 дней (21 приём пищи). Число дней влияет на рецепты, потребности, список покупок и заявку WhatsApp. Существующие сохранённые 7-дневные планы мигрируют в формат v2 без потери выбора; новый подбор стартует с 3 дней.

Отметка «Уже есть дома» по ингредиенту исключает его из магазинного заказа, суммы и WhatsApp. Ингредиент остаётся в рецепте и переносится в отдельный блок «Уже есть дома» с необходимым количеством, откуда его можно вернуть в магазинную корзину. Отметки сохраняются только в локальном хранилище браузера. Новое меню сбрасывает отметки «дома»; чекбокс «Куплено» независим. При составлении меню домашние продукты не зависят от складского остатка Паллеты. Мясо по-прежнему находится отдельно от ассортиментной корзины.

Для CSV используем наш технический ключ `PALLETA_TRADE_HALL` (это не код/UUID 1С); реальная ссылка склада должна быть проверена в УТ. ### Формат единственного утверждённого CSV

Все названия столбцов обязательны, один магазин и один вид цены:

```csv
store_key;internal_code;sku_code;price_type;club_price;price_unit;available_quantity;stock_unit;captured_at
PALLETA_TRADE_HALL;УТ-00003202;3202;Оптовая, RUB;54,90;кг;20;кг;2026-10-09T18:00:00+03:00
```

Вторая строка полностью **тестовая**. Для SKU с продажей упаковками обе единицы = `pack`, а цена указывается за 1 упаковку. Нельзя выгружать сюда закупочные цены, внутреннюю экономику, клиентов, токены и исходные полные остатки.

Прогон без изменений каталога:

```powershell
py sync_ut_catalog.py --csv D:\PalletaExport\ut_public_catalog.csv --store-key "PALLETA_TRADE_HALL" --price-type "Оптовая, RUB" --dry-run
```

Только после сверки с магазином и настройки GitHub-авторизации:

```powershell
powershell.exe -NoProfile -File D:\PalletaMenu\run_1c_sync.ps1 -StoreKey "PALLETA_TRADE_HALL" -PriceType "Оптовая, RUB"
```

## Сверка экспортов 13.10.2026 и безопасный импорт

Из обычного интерфейса УТ получены `12(1).xlsx` и min-max `13.10.2026.xlsx`. Подготовлен [READ-ONLY импортёр](./tools/stage_minmax_ut.py), [контрольная карта 21 SKU](./tools/sku_identity_review.json) и [инструкция первого запуска](./tools/README_STAGE.md). Проверено на двух исходниках: у 20 позиций есть кандидат внутреннего кода, один товар не сопоставлен; **только одна пара проверена до уровня «датированный снимок»**, остальные требуют редакционного подтверждения фасовки/эквивалентности. Исходные Excel и QA с остатками остаются локальными.

**Критическое правило:** `Номенклатура.Код для поиска` не уникален. Действующий валидатор `sync_ut_catalog.py` теперь проверяет **обе колонки**: `internal_code` (например, `УТ-00003202`) и `sku_code` (например, `3202`). Экспорт без обоих полей или с несогласованной парой блокируется. Текущие значения `products.json` остаются историческими, статуса live у них нет.

## Статус

- **Готово:** приложение на Pages, логика корзины, подбор аналогов, код валидатора единственного экспорта УТ, локальные тесты.
- **Не сделано:** реальная регламентная выгрузка из УТ 11, подтверждение вида цены, магазина и реального доступного остатка, настройка заданий Windows, сопоставление всех товарных кодов (сейчас 2/21).
- Пока нет подтверждённой свежей выгрузки, интерфейс не должен обещать актуальный остаток или точную итоговую стоимость. Даже после подключения данные на сайте не являются резервом: магазин подтверждает цену и наличие при приёме заказа.

Данные `products.json` публично доступны через GitHub Pages. Публиковать разрешено только одобренные значения и безопасную квоту доступного количества.
