# Паллета — семейное меню на неделю

**Вид цены УТ 11 для владельцев клубной карты:** «Оптовая, RUB» (подтверждено владельцем 10.10.2026). Обычная «Розничная, RUB» и «Закупочная, RUB» не используются в меню. Фактическое применение клубной цены на кассе и остаток магазина требуют сверки.

Публичный пилот: **7 дней × завтрак, обед и ужин (21 приём пищи)**, 42 редакционных рецепта, предварительная недельная корзина с фасовками, подбор совместимых товаров и замена блюда, если подтверждённого остатка недостаточно. Порции и рецепты требуют кулинарной проверки. Не резервирует товар и не принимает оплату.

Сайт: https://shmlr.github.io/palleta-menu/

## Структура

- `index.html`, `app.js`, `core.js`: интерфейс и расчёт.
- `products.json`: **публичный** ограниченный список SKU с ценами и доступностью. Текущие значения — исторические/неподтверждённые, пока не запущен импорт.
- `recipes.json`: рабочая рецептурная база, не копия всей закрытой библиотеки berbena.pro.
- `assets/palleta-logo.webp`: оригинальный фирменный знак Паллеты; на странице также ссылка на berbena.pro.
- `sync_ut_catalog.py`: строгая проверка и обновление публичного каталога из **одной** утверждённой CSV базы **1С УТ 11**.
- `run_1c_sync.ps1`: запуск для Windows и публикация через Git после успешных проверок.
- `test_sync_ut_catalog.py`, `test_core.cjs`, `test_ui.cjs`: локальные тесты.
- `.github/workflows/pages.yml`: развёртывание GitHub Pages.
- [`1C_SYNC_SETUP.md`](./1C_SYNC_SETUP.md): инструкция настройки экспорта и задания на ПК магазина.

## Решение по 1С (09.10.2026)

**Владелец подтвердил:** цены из УТ 11 передаются в Розницу. Для меню выбрана одна база-источник: **УТ 11, клубная цена + доступный к заказу остаток конкретной точки**. Розница остаётся для кассовой и выборочной контрольной сверки, но не является источником отдельного CSV и не требуется для планового обновления сайта.

Из УТ необходимо выбрать **вид «Оптовая, RUB», который**, который передаётся в Розницу для продажи с клубной картой, и проверить его на контрольном кассовом чеке. Остатки должны быть **доступными для продажи**, после резервов и исключений, а не общими складскими балансами.

### Формат единственного утверждённого CSV

Все названия столбцов обязательны, один магазин и один вид цены:

```csv
store_key;sku_code;price_type;club_price;price_unit;available_quantity;stock_unit;captured_at
STORE_KEY_FROM_1C;УТ-00003202;Оптовая, RUB;54,90;кг;20;кг;2026-10-09T18:00:00+03:00
```

Вторая строка полностью **тестовая**. Для SKU с продажей упаковками обе единицы = `pack`, а цена указывается за 1 упаковку. Нельзя выгружать сюда закупочные цены, внутреннюю экономику, клиентов, токены и исходные полные остатки.

Прогон без изменений каталога:

```powershell
py sync_ut_catalog.py --csv D:\PalletaExport\ut_public_catalog.csv --store-key "ВАШ_КЛЮЧ_ТОЧКИ" --price-type "Оптовая, RUB" --dry-run
```

Только после сверки с магазином и настройки GitHub-авторизации:

```powershell
powershell.exe -NoProfile -File D:\PalletaMenu\run_1c_sync.ps1 -StoreKey "ВАШ_КЛЮЧ_ТОЧКИ" -PriceType "Оптовая, RUB"
```

## Статус

- **Готово:** приложение на Pages, логика корзины, подбор аналогов, код валидатора единственного экспорта УТ, локальные тесты.
- **Не сделано:** реальная регламентная выгрузка из УТ 11, подтверждение вида цены, магазина и реального доступного остатка, настройка заданий Windows, сопоставление всех товарных кодов (сейчас 9/21).
- Пока нет подтверждённой свежей выгрузки, интерфейс не должен обещать актуальный остаток или точную итоговую стоимость. Даже после подключения данные на сайте не являются резервом: магазин подтверждает цену и наличие при приёме заказа.

Данные `products.json` публично доступны через GitHub Pages. Публиковать разрешено только одобренные значения и безопасную квоту доступного количества.
