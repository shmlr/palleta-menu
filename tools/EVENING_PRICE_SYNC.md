# Паллета v1.6 — вечерние клубные цены из min-max

## Статус на 14.10.2026

Письмо `Паллета 1С - Меню` от `palleta.store@yandex.ru` доставлено в 19:00:13 МСК. Вложение `.xls` имеет 302 товарные строки, из них 215 с числовым показателем «Свободный остаток». Это подтверждение **доставки по расписанию**; автоматическая публикация сайта до включения следующего шага отдельно НЕ подтверждена.

Разделяем **доставку**, **проверку**, **публикацию**. В публичный `products.json` можно помещать только разрешённую **датированную справочную клубную цену**. Данные закупки, остатки, маржа, излишки, поставщики, сырой Excel в GitHub не отправляются. Сведения `availability` остаются `unknown`. Без карты «Оптовая, RUB» не обещается.

## Что уже подготовлено

- `tools/club_price_allowlist.json`: только картофель с независимой верификацией пары кодов; шесть остальных прежних цен остаются неподтверждёнными для автоматического импорта; исключены мясо, зелень с неподтверждённой единицей, яйца и упаковки без подтверждённой конверсии.
- `tools/import_minmax_email.py`: безопасный локальный обработчик настоящего двоичного `.xls` (не переименованного `.xlsx`). Зависимость `xlrd==2.0.2`. Сначала **DRY RUN**; запись только при явно заданном `--write`.
- `test_minmax_email_import.py`: автопроверки на искусственных XLS без публикации сырых файлов. В CI дополнительно `xlwt==1.3.0` только для создания тестового XLS.

Проверяется: отправитель, точная тема, имя файла и время отчёта (+03:00), близость времени письма и отчёта (120 секунд), свежесть отчёта (не более 8 ч), контракт заголовков, отсутствие повторных кодов, точная сопоставленная строка, единицы и тип цены, изменение не более 50% от предыдущей справочной цены и более новая дата отчёта. При нарушении любого правила — **STOP без обновления**. Слишком сильные реальные изменения цены требуют ручного контроля. В качестве доказательства продажи и наличия снимок не используется.

## Как применить вручную (на доверенном компьютере)

Сохраните только доверенное вложение в **закрытую локальную папку вне GitHub**. Для примера письма от 14.10:

```powershell
py -m pip install xlrd==2.0.2
py tools/import_minmax_email.py `
  --xls "D:\PalletaExport\Отчет_Паллета 1С - Меню_2026-10-14 19-00-13.xls" `
  --sender "palleta.store@yandex.ru" `
  --subject "Паллета 1С - Меню" `
  --email-sent-at "2026-10-14T19:00:13+03:00"
```

Если `PASS_DATED_REFERENCE_ONLY` и изменения проверены, разрешить `--write`; это **обновит только локальный каталог**. Публикация `products.json` в GitHub делается отдельным разрешённым шагом после повторных тестов; не запускать автоматический `git add .`, чтобы случайно не отправить сырой XLS.

## Этап полной автоматизации

Вход с Gmail до выполнения `tools/import_minmax_email.py` требует отдельной интеграции с авторизацией. Самый простой путь — периодическая задача ChatGPT после 19:00, читающая подключённый Gmail, проверяющая только SKU из актуального `approved` (сейчас картофель) и обновляющая GitHub исключительно через предварительно проверенный PR. Если запланированная задача не имеет доступа к Gmail/GitHub, она должна сообщить об ошибке, а не утверждать, что цены обновлены. Альтернативный самостоятельный режим потребует один раз предоставить OAuth Gmail и безопасные GitHub credentials, которые **нельзя помещать** в публичный репозиторий.

Следующее расширение allowlist поштучными товарами, зеленью, другими видами номенклатуры — только после верификации единиц, фасовок и внутренних кодов. Наименование «Свободный остаток» в отчёте не удостоверяет физическую доступность на полке; публикация наличия требует отдельного Gate.

**Ни в каком режиме скрипт не пишет в УТ 11, не меняет расширения, не создаёт резервы и документы.**

## Целевая ежедневная цепочка после 19:00 МСК (НЕ АКТИВНА)

1. **Триггер:** получение после 19:00 МСК нового письма с точной темой `Паллета 1С - Меню`; не запуск по одному лишь времени. Один message ID обрабатывается не более одного раза; после сбоя повтор допустим лишь идемпотентно. Проверять целостность скачанных байтов до парсинга; никогда не получать XLS из случайных пересылок.
2. **Приватная обработка:** хранить XLS только во временной приватной директории, не передавать сырой Excel в GitHub, CI-артефакты и логи. Проверять BIFF8, единственный лист, заголовки и footer, отсутствие повторных внутренних кодов, неизменность структуры, дату отчёта, свежесть и отсутствие превышения порога изменения цены.
3. **SKU Gate:** сверять `tools/club_price_allowlist.json` (schema 3) с независимым `tools/sku_identity_review.json` и `products.json`. Требовать точное соответствие внутреннего кода, поискового кода, имени, единицы и шага покупки. Сейчас автообновление возможно только для картофеля `УТ-00003202|3202`. `кг1`, фасованное `шт` и зелень `шт/пучок` запрещены до отдельного подтверждения; мясо исключено. Пустая цена разрешённого SKU, дубликат или расхождение — STOP.
4. **Стадия обновления:** после PASS создавать только приватную временную копию каталога, обновлять исключительно разрешённые датированные клубные цены; сохранять `availability=unknown`, `stock_quantity=null`. Формировать минимальный diff только `products.json` с проверкой запрещённых изменений. Если ни одна цена не изменилась, не создавать пустой релиз; дату среза можно менять только при полном PASS и действительном новом письме.
5. **Release Gate:** создавать отдельный PR, выполнять `test.yml` (unittest, расчёты, UI, реальный Chrome). **Только при полном PASS**, отсутствии запрещённого diff и подтверждённой политике публикации разрешён merge в `main`. После merge отдельно ждать PASS Pages deployment и live Chrome smoke для точного commit. При FAIL сохранять прежние публичные файлы и формировать отчёт STOP с причиной без конфиденциальных данных.
6. **Секреты и запуск:** нужен отдельный исполняющий контур с Gmail OAuth read-only, правом открывать PR и безопасным хранилищем секретов. GitHub workflow сам по себе НЕ имеет доступа к подключённому Gmail ChatGPT. Требуется выполнить реальный сквозной тест на новом письме после 19:00; только после этого менять статус на ACTIVE. **Контрольные состояния:** `MAIL_RECEIVED` → `XLS_VALIDATED` → `IDENTITY_PASS` → `PR_TESTS_PASS` → `MERGED` → `PAGES_LIVE_PASS`; при любом отказе `STOP_NO_PUBLICATION`.
