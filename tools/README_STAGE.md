# Паллета: сверка UT + min-max (без изменения 1С)

**Текущий способ: обычный интерфейс УТ («Такси»).** Не требуется Конфигуратор, внешний `.epf`, COM, токены 1С или доступ из GitHub в локальную сеть магазина.

## Исходные данные и ограничения

- `12(1).xlsx`: ведомость склада «Паллета Петра 1» с `Номенклатура.Код` (внутренний код), `Номенклатура.Код для поиска`, номенклатурой, единицей и **учётным** остатком.
- `13.10.2026.xlsx`: выгрузка min-max, `Код` (внутренний код УТ), **`Цена Оптовая`** (клубная цена), `Свободный остаток` и прочие служебные поля.
- Оба файла — **датированные снимки** на 13.10.2026. Данные **не** актуализируются автоматически и **не** подтверждают физическое наличие товара на полке.
- «Оценка» из ведомости и «Цена» закупки из min-max **не используются** для цены на сайте.
- Исходные Excel содержат внутренние данные, в публичный GitHub **не загружать**.

## Безопасный контур (подготовлен)

1. Идентификация SKU — обязательная **пара** `(Номенклатура.Код, Номенклатура.Код для поиска)`. Короткий поисковый код встречается у разных товаров, поэтому **одно поле не является уникальным идентификатором**.
2. `sku_identity_review.json` — контрольные сопоставления 21 позиции. В остальных случаях статус `REVIEW_PENDING`: даже совпадение названия само по себе не разрешает автоматически менять фасовку или заменять бренд.
3. `stage_minmax_ut.py` **только читает** два локальных XLSX, сверяет пары, проверяет название и единицу товара, отмечает расхождения свободного и учётного остатка, отсутствующую клубную цену и спорную фасовку.
4. Результат — **локальный JSON-аудит** (`reports/`). Он никогда не должен использоваться как live-выгрузка в `products.json`.
5. Полный `products.json` меняется только после отдельной проверки клубной цены, единицы упаковки, физически доступного остатка и свежести среза. Покупатель должен видеть «наличие уточняется», пока данных нет.

## Пробный запуск на локальном ПК

Скачайте оба Excel отчёта из обычной УТ и min-max. Положите их рядом с проектом, но **не коммитьте**.

```powershell
py stage_minmax_ut.py --stock "D:\PalletaExport\12(1).xlsx" --minmax "D:\PalletaExport\13.10.2026.xlsx" --as-of 13.10.2026 --output "D:\PalletaExport\reports\audit_2026-10-13.json"
```

Встроенных библиотек Python достаточно, сторонние модули для первого этапа не нужны. Если изменилась структура или дата отчёта, скрипт останавливается.

## Состояние

Проверено на переданных файлах 13.10.2026: 21 позиция, **20 пар внутренних кодов кандидатов**, одна позиция не сопоставлена; по большому отчёту **множество коллизий коротких кодов**. На этом этапе ни один остаток не опубликован как текущий, карта рецептов и номенклатура магазина не изменялись автоматически.

Это **контрольная стадия**, не автоматическое подключение min-max к GitHub. Перед включением регулярной публикации необходимо установить происхождение даты/времени среза в Excel и подтвердить, что формула «Свободный остаток» соответствует реально доступному количеству с учётом Simple WMS и брака.

Содержимое XLS проверено в режиме только чтения по исходному MIME без публикации файла.

Структура вложения: **301 товарная строка**; колонка `Код` с внутренним кодом УТ, `Наименование`, `Цена Оптовая`, `Свободный остаток`. Цена числовая у 301 строк, свободный остаток числовой у **215 строк**, у **86** значения отсутствуют: **не считать пустую ячейку нулём**. Отчёт также содержит служебные колонки `Цена`, `Сумма излишков`, `Дней запаса`; исходник не подлежит загрузке в публичный GitHub.

Контрольные товары из вложения:

- Картофель: `УТ-00003202`, клубная цена **49,96 ₽/кг**, `Свободный остаток` **699,472** (единица подтверждалась в УТ отдельно).
- Рис Мистраль Янтарь 900 г: `УТ-00001079`, артикул `10213`, клубная цена **179,97 ₽/шт**, `Свободный остаток` **5**.

**Статус:** доставка и содержимое контрольных строк PASS. Но письмо связано с вариантом `<<Новая 03.10.2026 18:33:18>>`, включает группу `РД (301)` и не доказывает полноту всех 21 SKU. У XLS **нет отдельного надёжного `captured_at` для каждой строки**; время отправки письма и время запуска расчёта нельзя без проверки заменять временем фактического среза доступности. Профиль, фильтр склада и отсутствие создания документов ещё необходимо проверить. Регулярный автозапуск и публичное обновление `products.json` **не включены и не подтверждены**.

**Новый формат требует отдельного импортёра:** существующий `tools/stage_minmax_ut.py` читает **.xlsx** и не должен получать присланный **.xls** под другим расширением. До адаптации конвертера и повторных тестов `.xls` используется только для ручного безопасного аудита.
